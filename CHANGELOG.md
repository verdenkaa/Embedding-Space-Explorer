# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект придерживается [семантического версионирования](https://semver.org/lang/ru/).

## [0.9.1] — 2026-10-19

Точечная стабилизация визуализации по итогам приёмки: видимость сетки в 3D,
читаемость подписей осей, возврат насыщенной палитры данных и однозначное
оранжевое выделение.

### Изменено

- Frontend:
  - **3D/4D-сетка снова видима**: линии пола рисуются отдельным усиленным
    токеном `--color-grid-line-3d` (наклонные 1px-линии WebGL теряют около
    половины контраста на сглаживании, поэтому значение сильнее, чем у
    пиксельной 2D-сетки; 2D оставлена прежней);
  - **режим «цифры» читается**: подписи-спрайты уменьшены с 0.26–0.30 до
    0.085–0.11 мировых единиц (раньше закрывали треть сцены), растрируются
    в 44px и пересоздаются после загрузки встроенного JetBrains Mono
    (`document.fonts.ready`), текстуры помечены SRGBColorSpace;
  - **деления осей — действительные «красивые» значения**: шаги 1/2/5·10^k
    из `makeTicks` по сырому диапазону оси (как в 2D) вместо шестизначных
    хвостов вида 3.518955;
  - **каждая ось 3D подписана целиком**: числовые деления вдоль своей оси
    (со смещением в разные стороны у пересечения — без наложений) плюс имя
    оси у положительного конца (PC1/PC2/PC3 или индексы сырых осей); ранее
    имена жались в углах пола под гигантскими цифрами и «подписанной»
    выглядела только верхняя ось; оси растянуты на [-1.15, 1.15] и окрашены
    по осям (бирюза/синий/фиолет, токены `--color-axis-x/y/z`);
  - **насыщенная палитра данных возвращена** (точки = легенда = бейджи):
    FN/MTH бирюзовый #45d6c5, CLS-семейство синий #63a9ff, секции документов
    зелёный #7bd88f, прочее серый #8fa0ae; кластеры — снова s=0.62/l=0.58;
    файловые типы — насыщенный различимый набор без оранжевого (Python
    #58a6ff, JavaScript #b8d55a, TypeScript #39c5cf, Markdown #c586f0,
    JSON #ef7fae, config #5fd38a);
  - **цвета на экране совпадают с hex**: vertex-буферы получают линейные
    значения (sRGB→linear в `hexToRgb`), иначе three.js осветлял точки до
    пастели; точка, её легенда и её цвет в 2D теперь одинаковы.

### Исправлено

- Frontend:
  - **выделение снова горит оранжевым и оранжевый зарезервирован**: маркеры
    выделения (свечение выбранных точек, кольцо активного фрагмента,
    crosshair в 2D) используют янтарный #e8b45a (`--color-accent-amber`);
    ни один цвет точек/файлов/кластеров его не переиспользует — палитра
    кластеров пропускает оранжевый диапазон тонов 10°..70°, а регрессионный
    тест валится при попытке отдать янтарный какой-либо категории точек;
  - **маркеры выделения больше не теряются**: это оверлеи, а не геометрия
    сцены — они не проходят depth-тест и рисуются последними (renderOrder
    25–27), поэтому совпадающая глубина с собственной точкой (поведение
    зависело от драйвера) больше не прячет выделение; эффект «точка стала
    белой и появился кружок» устранён.

## [0.9.0] — 2026-10-16

Переработка интерфейса в стиле тёмной инженерной IDE, удаление следов
разработки, координатная сетка и окраска по типу файла.

### Добавлено

- Frontend:
  - **координатная сетка — три режима** («выкл / простая / цифры», общая для
    2D и 3D/4D, переключатель в ViewBar): «простая» — равномерная сетка без
    подписей; «цифры» — сетка плюс действительные значения координат вдоль
    осей и имена осей (PC1/PC2…, индексы сырых осей). В 2D значения берутся
    из единиц проекции; в 3D/4D — из обратного преобразования display-фита
    (raw = display·extent + center), спрайты с цифрами прозрачны для выбора
    точек и утилизируются при размонтировании. Режим сетки — часть состояния
    представления; чистая математика — `space/gridMath.ts` (с тестами);
  - **окраска по типу файла** — третий режим «цвет: файл» рядом с «тип/кластер»:
    точки, 2D-график и легенда окрашиваются по расширению файла тем же цветом,
    что и бейдж этого файла в дереве (единый источник — `space/palette.ts`);
  - **шрифты в поставке**: JetBrains Mono (технические данные, код, координаты)
    и Inter (интерфейс) — latin+cyrillic woff2, лицензия OFL, без внешнего CDN
    (приложение работает офлайн);
  - **тест единого источника цветов**: `palette.test.ts` разбирает
    `theme/tokens.css` и сверяет canvas/WebGL-палитру (`palette.ts`) с
    дизайн-токенами — расхождение ловится тестом.
- Backend: `color_by` в конфиге сохранённого эксперимента принимает «file».

### Изменено

- **Интерфейс — тёмная графитовая палитра инженерной IDE**: поверхности
  (#1e1f22 / #252629 / #2b2d30, область графика #202124), тонкие границы
  (#393b40 / #45474d), спокойный текст (#dfe1e5 / #a4a7ad / #777b83), единый
  синий акцент (#3574f0) вместо прежнего бирюзового, компактная плотность
  (базовый 12px, скругления 3–5px, элементы управления ~22–28px); topbar и
  статусбар — графитовый «хром», вкладки разделов/корпуса — тонкое синее
  подчёркивание, залитая первичная кнопка; тема Monaco и шрифт редактора
  приведены к палитре; декоративный логотип из шапки убран;
- **цвета фрагментов и файлов — из единой палитры**: фрагменты FN #6c9ef8 /
  MTH #b39ddb / CLS #e8a36b (+ секции и fallback), файлы по типу
  (python / javascript / typescript / markdown / json / config); бейдж в дереве,
  точка и легенда согласованы (цвет никогда не единственный признак — текст
  всегда присутствует);
- Версии: приложение 0.9.0 (backend, frontend package.json/package-lock.json);
  схема данных не менялась (7).
- Тесты: backend **189** (+1: приём `color_by` «file» и отклонение неизвестного
  режима), frontend **284** (+14: синхронизация палитры с токенами, окраска по
  файлу, математика сетки, контролы ViewBar, режимы сетки в 2D).

### Удалено

- **Следы разработки с продуктовой поверхности**: StatusBar больше не показывает
  «· этап 5»; вкладки разделов — без бейджа «этап N»; DiagnosticsPanel — просто
  «Диагностика» (без «— Этап 0») и без колонки «Этап» в таблице зависимостей;
  из API `/api/health` убрано поле `planned_stage`; из README, CHANGELOG,
  `docs/` и комментариев кода удалены нумерация этапов и ссылки на разделы
  спецификации (продукт представлен как завершённый; история версий сохранена).

## [0.8.0] — 2026-10-16

Метрики, эксперименты, экспорт.

### Добавлено

- Backend (db schema **v6**, аддитивная миграция v5→v6 с бэкапом; новых
  зависимостей нет — trustworthiness из уже установленного scikit-learn):
  - **`metrics/`** — минимальный набор метрик качества, каждое значение с
    пояснением и счётчиками (число без интерпретации запрещено):
    `neighbor_retention@k` (доля k ближайших соседей ИСХОДНОГО пространства
    (cosine), оставшихся в k ближайших проекции (euclidean)),
    `trustworthiness@k` (sklearn; при малой выборке k честно уменьшается и
    фактическое k сохраняется), `relation_precision@k` и
    `relation_coverage@k` — согласие топ-k соседей исходного пространства с
    ИЗВЕСТНЫМИ структурными связями. Правила неполноты корпуса:
    неизвестная пара никогда не считается негативом, знаменатели строятся
    только по известным парам, нет данных → `null` + warning (никогда
    «подозрительный 0.0»). Выборка детерминирована (seed) и сохраняется с
    результатом; задача `metrics` идемпотентна (fingerprint), устаревание по
    подписи векторов; пересечение проекции и эмбеддингов явное (warning);
  - **`experiment_manager/`** — сохранённые эксперименты: POST /experiments
    валидирует ВСЕ ссылки (неизвестные → 400 с точным списком; мёртвые id
    выделения отбрасываются и учитываются) и пишет снимок контекста на
    момент сохранения (корпус, подпись векторов, версии приложения/схемы,
    устаревание ссылок, значения метрик — сравнение позже без пересчёта);
    GET /experiments/{id} возвращает live-статус (missing/stale) — открытие
    перечисляет отсутствующее честно, а не подменяет артефакты молча; имя
    уникально; выделение ≤ 5000 id с флагом усечения;
  - **`exporters/`** — CSV (с BOM для Excel) и JSON: точки проекции
    (координаты + полная трассировка + признак устаревания), связи
    (с фильтрами браузера, концы разрешены до путей/символов), выделение
    (POST со списком id; недостающие — в заголовке
    `X-Ese-Missing-Fragments`; пустой список — 422), запуск метрик
    (значения + пояснения + параметры + версии библиотек), эксперимент
    (конфиг + снимок + live-статус — полный пакет интерпретации);
    `Content-Disposition: attachment`.
- Frontend:
  - **панель «Метрики»** (SPACE, под «Срезом», свёрнута по умолчанию —
    метрики вторичны по отношению к пространству): выбор проекции
    (по умолчанию активный вид) или режим «без проекции — только связи»,
    явная форма k/выборка/seed → задача на канале анализа; результаты
    компактными раскрывающимися блоками (значение, k, счётчики, пояснение),
    «нет данных» вместо null, бейдж «устарел», предупреждения, история
    запусков, экспорт JSON и удаление;
  - **карточка «Эксперименты»** (EXPERIMENTS): сохранение текущего
    состояния SPACE (виды и проекции, срез — saved_slice_id или
    определение, раскраска кластерами, группы, выделение, метрики) под
    именем; список со сводкой и значениями метрик на момент сохранения;
    «Открыть» восстанавливает живые ссылки и показывает ОТЧЁТ
    (восстановлено / не восстановлено с причинами); сравнение двух
    экспериментов таблицей (конфиги + контекст сохранения + метрики);
    двухшаговое удаление; экспорт JSON;
  - **меню «⤓ Экспорт»** (ViewBar): PNG живых сцен и 2D-графиков
    (клиентский захват canvas; WebGL рендерится с `preserveDrawingBuffer` —
    экспортируется ровно то, что на экране), CSV точек активной проекции,
    CSV выделения, CSV всех связей; download-хелпер читает имя файла из
    `Content-Disposition`;
  - `savedExperimentsStore` (чистые `captureSpaceState`/`applyExperiment`),
    метрики в `analysisStore`, `clusterRunId` в spaceStore и `savedSliceId`
    в срез-оверлее (эксперимент восстанавливает точные артефакты);
  - честные подписи: StatusBar, описания секций, StartScreen и
    DiagnosticsPanel больше не обещают скорое появление метрик;
    исправлена предсуществующая ошибка рендера JobProgress на неполной
    job-фикстуре (моки приведены к форме JobInfo).

## [0.7.0] — 2026-10-16

Срезы, соседи, связи и кластеры.

### Добавлено

- Backend (db schema **v5**, аддитивная миграция v4→v5 с бэкапом; новых
  зависимостей нет — DBSCAN из уже установленного scikit-learn):
  - **`slice_engine`** — математический срез ИСХОДНОГО D-мерного пространства:
    `d(x) = dot(x − p, n)`, слой `|d| ≤ t/2`, `p = центроид + position·n`.
    Нормали MVP: ось пространства, направление PCA (детерминированный
    full-SVD), явный вектор. `POST /slices/compute` синхронно выдаёт
    координату `u(x)` вдоль нормали для КАЖДОГО фрагмента (клиент крутит
    позицию/толщину без запросов; сервер считает `in_layer` по тем же
    округлённым значениям — счётчик и маска никогда не разойдутся).
    `saved_slices` хранят РАЗВЕРНУТЫЙ единичный вектор — сохранённый срез
    воспроизводим даже после изменения данных; CRUD срезов;
  - **`neighbor_search`** — точный kNN (brute-force numpy, без приближённых
    индексов) по ИСХОДНЫМ эмбеддингам: cosine (по умолчанию) / euclidean,
    self исключается, `POST /neighbors` возвращает score+distance+полную
    трассировку и подпись «по исходным эмбеддингам, не по проекции»;
  - **`relation_providers`** — структурные отношения с непоказным provenance:
    задача извлечения (полная перезапись origin=extracted): imports через
    tree-sitter (Python: dotted/relative → файл или `__init__.py`; JS/TS:
    относительные пути, `index.*`, `require()`) + belongs_to по
    parent_symbol_path; концы — файл И/ИЛИ фрагмент (верхнеуровневый импорт
    не принадлежит фрагменту — файловый конец честен); неразрешённые
    specifiers считаются в предупреждениях, а не выдумываются. Импорт
    формата **`ese-relations/v1`** (JSON): построчный отчёт
    (добавлено/дубликаты/не разрешено с причинами), разрешение концов по
    symbol_path или наименьшему содержащему фрагменту строки, файловые концы
    валидны. Ручные связи (fragment→fragment) + удаление любых; браузер с
    фильтрами (fragment/file/kind/origin) и глобальными счётчиками;
  - **`clustering_methods`** — DBSCAN по ЯВНОМУ пространству: исходные
    векторы (cosine/euclidean) или координаты одной проекции (только
    euclidean; cosine по осям проекции отклоняется с объяснением). Задача
    `clustering`, fingerprint-идемпотентность, метки в
    `cache/clustering/<id>.npz` (повреждение → честные 409), stale по
    подписи векторов, шум (−1) — отдельный счётчик, не «смысл»;
  - **ручные группы** (`fragment_groups`): именованные наборы ID фрагментов
    из текущего выделения, уникальность имён (409), неизвестные фрагменты
    отклоняются (400), члены каскадом покидают группу при удалении
    фрагментов; независимы от автокластеризации;
  - 25 новых тестов: геометрия среза на синтетике (включительные границы,
    нулевая/полная толщина, ортогональность PCA-направлений), соседи на
    наборе с ручным расчётом, извлечение imports/belongs_to на мини-проекте
    с известной структурой (numpy → предупреждение, не связь), идемпотентная
    перезапись, импорт-отчёты и матрица ошибок формата, DBSCAN-геометрия,
    API-потоки кластеризации/групп/срезов, миграция v4→v5. Итого backend
    **170** (+2 opt-in real_model).
  - надёжность хранения: SQLite-прагмы `foreign_keys`/`synchronous`
    (per-connection) теперь применяются к КАЖДОМУ соединению пула через
    connect-event — каскады больше не зависят от того, какое соединение
    обслужило запрос (латентная проблема с ранней версии); порядок flush при
    создании группы задан явно.
- Frontend:
  - **левая панель SPACE**: все четыре вкладки живые — FRAGMENTS /
    **NEIGHBORS** (k/метрика, ранжированный список, честная подпись, клик —
    переход) / **RELATIONS** (исходящие/входящие, текстовые бейджи и глифы
    типов — не только цвет, происхождение, уверенность, файловые концы) /
    **CLUSTERS** (форма DBSCAN с явным пространством, запуски со
    stale/шумом, «На сцену», ручные группы из выделения);
  - **панель «Срез»** под графиками: запуск+нормаль (ось/PCA+индекс),
    слайдеры позиции/толщины (локальная математика — ноль запросов на тик),
    «в слое N из M», режимы «затемнять / только слой / все точки»,
    сохранённые срезы (применить/сохранить/удалить), постоянная оговорка
    «выборка в исходном пространстве, показ через проекцию»; срез НЕ
    применяется к облакам другого запуска — панель предупреждает;
  - **сцены**: затемнение/скрытие точек вне слоя (3D/4D/2D), маска среза
    также отсекает hover/pick/рамку; раскраска по кластерам (детерминированная
    палитра золотого угла, шум — серый, легенда с текстовыми ключами «кластер
    N»/«шум»/«без метки»); **линии структурных связей** активной точки в 3D
    (кнопка «⇄ Связи», чекбоксы типов со счётчиками, лимит 300, честный
    счётчик «не нарисовано»: файловые концы и точки вне облака);
  - **секция RELATIONS** (верхняя вкладка): браузер с фильтрами и
    пагинацией, «Извлечь связи» (задача с прогрессом), «Импорт JSON…» с
    полным отчётом, конструктор ручной связи с поисковыми пикерами
    фрагментов, удаление строк;
  - `analysisStore` (соседи/связи/кластеры/группы/срезы + собственный канал
    задач с polling), расширение `spaceStore` (оверлей среза, раскраска,

  - `vector_store`: .npz-кэш на запуск (ids/text_hashes/frag_hashes/vectors),
    атомарная запись, восстановление из повреждённого файла как из пустого;
  - запуск (run) идентифицируется fingerprint(model, mode, template, params);
    batch_size в fingerprint НЕ входит — уменьшение батча при нехватке RAM не
    инвалидирует кэш; разные модели/режимы никогда не смешиваются;
  - расчёт эмбеддингов фоновой задачей: кэш по hash(точный подготовленный текст),
    чекпоинты (отмена сохраняет посчитанное), prune устаревших/удалённых векторов
    после каждой переиндексации;
  - API: `GET /api/models`, `POST …/models/download`, `POST …/embeddings/compute`,
    `GET …/embeddings` (инвентарь + покрытие embedded/stale/missing);
  - db schema v2 (аддитивная миграция v1→v2 с бэкапом: таблица embedding_runs);
  - health: numpy/torch/sentence-transformers — обязательные зависимости;
  - 107 тестов (fake-provider для логики кэша/отмены/покрытия; opt-in
    `-m real_model` с настоящей моделью) + реальный E2E: download → compute
    raw+context → coverage 21/21 → prune на реиндексе → досчёт.
- Frontend:
  - раздел EXPERIMENTS: каталог моделей (статус скачивания, кнопка загрузки с
    размером), режимы подготовки с точным превью шаблона, batch size, расчёт с
    прогрессом/отменой, таблица запусков с покрытием и кнопкой «Пересчитать»;
  - experimentStore (однонаправленная зависимость от projectStore); JobProgress
    генерализован и переиспользуется корпусом и экспериментами;
  - микрофикс индикатора устаревания: внеочередная проверка при фокусе окна +
    console.warn при сбое (диагностика «backend не перезапущен после патчей»);
  - 49 тестов (experimentStore, ExperimentsPanel, обновлённые секции).
- Документация: `docs/data-model.md` §6.5 (кэш векторов, fingerprint,
  инвалидация), development.md (real_model, добавление моделей), README
  (исправлена незамеченная ранее устаревшая плашка статуса).

## [0.1.0] — 2026-10-15

Обследование среды и каркас приложения.

### Добавлено

- Структура монорепозитория: `backend/` (Python, FastAPI), `frontend/` (React, TypeScript, Vite),
  `docs/`, `scripts/`.
- Backend:
  - фабрика приложения `create_app()` с конфигурацией через переменные окружения (`ESE_HOST`,
    `ESE_PORT`, `ESE_DATA_DIR`, `ESE_FRONTEND_PORTS`);
  - эндпоинт диагностики `GET /api/health`: версия приложения и схемы данных, версия Python,
    платформа, каталог данных, статусы проверок, версии обязательных и запланированных
    зависимостей;
  - middleware `LocalOnlyMiddleware`: запросы принимаются только с loopback-`Host`
    (`127.0.0.1` / `localhost` / `::1`), изменяющие методы (POST/PUT/PATCH/DELETE) с
    нелокальным `Origin` отклоняются (защита от DNS rebinding / CSRF);
  - CORS разрешён только для локальных адресов фронтенда;
  - сервер по умолчанию слушает только `127.0.0.1:8000`;
  - тесты pytest (health + security), ruff, mypy (strict).
- Frontend:
  - каркас интерфейса в стиле «тёмная исследовательская IDE» (дизайн-токены);
  - панель диагностики с состояниями загрузка / онлайн / офлайн и понятными подсказками;
  - типизированный API-клиент и zustand-store состояния подключения;
  - разделы SPACE / CORPUS / RELATIONS / EXPERIMENTS показаны как запланированные
    (видимая недоступность, без «кнопок-обманок»);
  - vitest + @testing-library (тесты состояний панели и API-клиента), ESLint, tsc strict.
- Скрипты запуска одной командой: `scripts/dev.bat` и `scripts/dev.ps1` (Windows),
  `scripts/dev.sh` (Linux/macOS): проверка версий Python/Node, установка зависимостей,
  запуск backend и frontend.
- Скрипт всех проверок одной командой: `scripts/checks.bat` / `checks.ps1`
  (pytest, ruff, ruff format, mypy, vitest, eslint, tsc, build) с итоговой таблицей.
- Документация: `README.md`, `docs/architecture.md`, `docs/development.md`.
- Зафиксированные версии зависимостей: `backend/requirements*.txt`,
  `frontend/package-lock.json`.

### Исправлено

- Совместимость `dev.ps1` с Windows PowerShell 5.1: файл сохраняется в UTF-8 with BOM,
  пунктуация только ASCII, дочерние окна запускаются через `powershell -NoExit -Command`
  (без оператора `&&`), добавлено ожидание ответа backend перед открытием браузера.
- `pytest` запускается из любого каталога (bootstrap `sys.path` в `tests/conftest.py`
