# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект придерживается [семантического версионирования](https://semver.org/lang/ru/).

## [0.4.0] — 2026-10-16

Этап 3 — пространство и проекции.

### Добавлено

- Backend:
  - `projection_methods`: интерфейс метода проекции + каталог (добавление
    метода = одна запись в реестре); PCA (scikit-learn, svd_solver="full" —
    детерминированная без seed, сохраняет долю объяснённой дисперсии по осям;
    вырожденный вход даёт честные нули, не NaN) и UMAP (lazy-import numba с
    понятными ошибками при нехватке RAM/отсутствии пакета; random_state=seed —
    воспроизводимость проверена тестами; оговорка об искажении расстояний
    хранится вместе с методом); декларативные спецификации параметров
    (диапазоны, значения по умолчанию, choice) — единый источник для
    серверной валидации и UI-формы; неизвестные параметры отклоняются (400),
    скрытых значений нет;
  - кэш проекций: .npz на запуск (`cache/projections/<fingerprint>.npz`,
    ids/coords/axis_info), атомарная запись; повреждённый кэш отличим от
    пустого — API требует пересчёт (409) вместо выдачи «пустого облака»;
  - запуск проекции идентифицируется fingerprint(embedding_run, method,
    n_components, params, seed); идентичный пересчёт не плодит запуски;
    устаревание по подписи векторного кэша (ids+text_hashes): после
    реиндексации/пересчёта эмбеддингов проекция честно помечается stale;
    точки удалённых фрагментов не показываются (счётчик dropped_orphans);
  - задача проекции: один job считает 3D и 2D координаты (стадии с прогрессом,
    отмена между стадиями, предупреждение о неполном покрытии эмбеддингами);
    версии библиотек (numpy/scikit-learn/umap-learn) сохраняются в запуске;
  - API: `GET /api/projections/methods` (каталог с оговорками и доступностью),
    `POST …/projections/compute` (валидация параметров до очереди: 400/404/409
    с подсказками), `GET …/projections` (инвентарь + staleness + cache_ok),
    `GET …/projections/{id}/points` (координаты + полная трассируемость
    фрагмента одним запросом); проекции не стартуют во время активных
    embed/projection-задач (409);
  - db schema v3 (аддитивная миграция v2→v3 с бэкапом: таблица
    projection_runs); health: scikit-learn и umap-learn — обязательные
    зависимости;
  - 23 новых тестов (геометрия PCA на известных синтетических векторах,
    детерминированность UMAP с seed, валидация параметров, fingerprint,
    кэш/повреждения, подпись устаревания, полные API-потоки: compute →
    points → stale после реиндекса → пересчёт; PCA-вложенность XY(3D)==2D;
    миграция v2→v3 сохраняет запуски эмбеддингов существующих проектов)
    + opt-in real_model E2E: настоящая модель → эмбеддинги → PCA/UMAP,
    выданные координаты сверяются с независимым пересчётом PCA из
    сохранённых .npz-векторов (итог: backend 130 тестов + 2 opt-in
    real_model);
  - общие фейки тестов (FakeProvider) вынесены в conftest (этапы 2–3).
- Frontend:
  - раздел SPACE: полная компоновка «исследовательской IDE» (ТЗ §4.2) —
    корпус слева, 3D-сцена / панель проекций / 2D-карта в центре, Monaco
    справа; все панели изменяемые (Allotment);
  - 3D-сцена (React Three Fiber): ОДИН батченный объект точек с
    буферными атрибутами (никаких компонентов на точку), цвета по типу
    фрагмента (та же группировка, что в корпусе), OrbitControls, тонкая сетка
    и деликатные оси, hover-подсказка (имя/путь/строки), клик — выбор,
    Ctrl-клик — добавление, режим «выделение области» (кнопка или Shift+drag,
    NDC-математика в чистых хелперах), кольца активного/выбранных (форма,
    а не только цвет), легенда со текстовыми бейджами, сброс камеры,
    Esc/клик по фону/кнопка снимают выделение, размер точек, состояния
    загрузка/пусто/ошибка;
  - 2D-проекция (canvas): оси с «красивыми» тиками в единицах проекции,
    подпись метода и осей (PC1/PC2, UMAP1/UMAP2), доля объяснённой дисперсии
    PCA, общий selection state с 3D, hover, клик, Shift+drag-рамка, явная
    оговорка «проекция всех точек · не срез» (срезы — этап 4);
  - панель управления проекциями: выбор векторного запуска, метод и его
    параметры (форма строится из серверного каталога), seed, «Построить
    проекцию (3D+2D)» с прогрессом/отменой, переключение видов между
    кэшированными проекциями с честными метками «устарела»/«кэш повреждён»,
    оговорка метода всегда видна;
  - синхронизация по id фрагмента: клик точки открывает файл и подсвечивает
    диапазон строк в Monaco (сценарий B), выбор фрагмента в корпусе
    подсвечивает точку в обеих сценах; множественное выделение показывается
    в списках фрагментов и статус-баре;
  - spaceStore (состояние представления) + расширения experimentStore
    (каталог/форма/инвентарь/задача проекций) и projectStore
    (selectedFragmentIds); координаты — только с сервера, клиентская
    математика ограничена view-трансформацией и пикнингом;
  - StatusBar: сегмент активной проекции (метод/точки/stale) и счётчик
    выделения; исправлена устаревшая плашка «этап 1»;
  - 74 новых теста (математика выделения/тиков/хит-теста, stores, 2D-клики и
    рамка через реальные pointer-события, состояния 3D-сцены с моком r3f,
    оркестрация SpaceSection, форма проекций; итог: frontend 123 теста).
- Документация: `docs/data-model.md` §6.6 (кэш проекций, fingerprint,
  подпись устаревания, db v3), architecture.md (модули этапа 3, версии
  three/r3f/drei/umap), development.md (как добавить метод проекции),
  README (статус этапа 3, сценарий исследования пространства).

### Изменено

- requirements: + umap-learn 0.5.12 (numba 0.68.0, llvmlite 0.50.0,

## [0.3.0] — 2026-10-15

Этап 2 — эмбеддинги и кэш.

### Добавлено

- Backend:
  - `embedding_providers`: интерфейс провайдера + sentence-transformers (CPU,
    lazy-import, batch-инференс с прогрессом и отменой между батчами); каталог
    из двух моделей (по умолчанию paraphrase-multilingual-MiniLM-L12-v2, 384d,
    с честным описанием ограничений; компактная all-MiniLM-L6-v2); скачивание
    весов в общий кэш `<data_dir>/models` фоновой задачей, далее офлайн;
    понятные ошибки при нехватке RAM на импорте torch (ТЗ §12);
  - `preparation`: режимы raw_fragment / context_enriched с явным шаблоном
    (path/symbol/kind/parent/language), точное превью через
    `GET /api/embeddings/preparation-preview`;
  - `vector_store`: .npz-кэш на запуск (ids/text_hashes/frag_hashes/vectors),
    атомарная запись, восстановление из повреждённого файла как из пустого;
  - запуск (run) идентифицируется fingerprint(model, mode, template, params);
    batch_size в fingerprint НЕ входит — уменьшение батча при нехватке RAM не
    инвалидирует кэш (ТЗ §12); разные модели/режимы никогда не смешиваются;
  - расчёт эмбеддингов фоновой задачей: кэш по hash(точный подготовленный текст),
    чекпоинты (отмена сохраняет посчитанное), prune устаревших/удалённых векторов
    после каждой переиндексации;
  - API: `GET /api/models`, `POST …/models/download`, `POST …/embeddings/compute`,
    `GET …/embeddings` (инвентарь + покрытие embedded/stale/missing);
  - db schema v2 (аддитивная миграция v1→v2 с бэкапом: таблица embedding_runs);
  - health: numpy/torch/sentence-transformers — обязательные зависимости;
  - 107 тестов (fake-provider для логики кэша/отмены/покрытия; opt-in
    `-m real_model` с настоящей моделью) + реальный E2E: download → compute
    raw+context → coverage 21/21 → prune на реиндексе → досчёт.
- Frontend:
  - раздел EXPERIMENTS: каталог моделей (статус скачивания, кнопка загрузки с
    размером), режимы подготовки с точным превью шаблона, batch size, расчёт с
    прогрессом/отменой, таблица запусков с покрытием и кнопкой «Пересчитать»;
  - experimentStore (однонаправленная зависимость от projectStore); JobProgress
    генерализован и переиспользуется корпусом и экспериментами;
  - микрофикс индикатора устаревания: внеочередная проверка при фокусе окна +
    console.warn при сбое (диагностика «backend не перезапущен после патчей»);
  - 49 тестов (experimentStore, ExperimentsPanel, обновлённые секции).
- Документация: `docs/data-model.md` §6.5 (кэш векторов, fingerprint,
  инвалидация), development.md (real_model, добавление моделей), README
  (статус этапа 2 — исправлена незамеченная ранее незаменённая плашка этапа 0).

### Изменено

- Версии: приложение 0.3.0, схема данных 3 (project.db v2).
- requirements: + numpy 2.4.6, torch 2.14.1+cpu (extra-index-url
  download.pytorch.org), sentence-transformers 6.1.0; mypy-оверрайды
  follow_imports=skip для тяжёлых ML-библиотек.

## [0.2.1] — 2026-10-15

### Добавлено

- Индикатор устаревания индекса: `GET /api/projects/{id}/staleness` — лёгкий
  зонд (полное сканирование по правилам проекта, но без хэширования

- 6 новых тестов (backend: сценарий dirty→reindex→clean; frontend: store и
  состояния кнопки). Итого: backend 91, frontend 39.

## [0.2.0] — 2026-10-15

Этап 1 — корпус и трассировка.

### Добавлено

- Backend:
  - `source_registry`: безопасное сканирование корней — исключения сервисных
    каталогов и glob-паттерны, защита от `../`/симлинков наружу, исключение
    секретов (`.env`, ключи, сертификаты) с явным предупреждением при ручном
    включении, лимит размера, детекция бинарников, отчёт «что пропущено и почему»;
  - `fragmentation`: tree-sitter-сегментация Python/JavaScript/TypeScript/TSX
    (функции, методы, классы, интерфейсы, enum; декораторы включены в диапазон),
    Markdown-секции по заголовкам (с игнорированием заголовков в code fences),
    fallback-чанки с перекрытием; стабильные детерминированные ID фрагментов
    (не зависят от номеров строк, различаются между файлами); парсинг-ошибки —
    предупреждения, не падение индекса;
  - `storage`: SQLite (WAL) на проект — files/fragments/jobs/meta,
    версионирование схемы с бэкапом перед миграцией, атомарная запись манифеста;
  - `jobs`: фоновое индексирование с прогрессом, предупреждениями и отменой
    (polling, без WebSocket); инкрементальность: неизменившиеся файлы и их
    фрагменты не пересчитываются;
  - API: projects (создание/список/удаление с подтверждением), files
    (список/детали/содержимое с повторной проверкой безопасности пути),
    fragments (поиск/детали), locate (строки → пересекающиеся фрагменты),
    changes (превью изменений без записи), jobs (статус/отмена), fs/list-dirs
    (браузер каталогов для выбора корней — только имена директорий);
  - единый конверт ошибок `{error: {code, message, hint}}`;
  - 90 backend-тестов (scanner, сегментация, стабильные ID, изменения, API,
    задачи, безопасность), fixture-проект с заведомо известными диапазонами строк.
- Frontend:
  - раздел CORPUS: дерево файлов, поиск фрагментов, список фрагментов файла,
    карточка выбранного фрагмента (symbol_path, строки, метод, стабильный ID);
  - Monaco-инспектор: только просмотр, тёмная тема ese-dark, подсветка активного
    фрагмента (цвет + линейка + маркер в gutter), обратная трассировка —
    выделение строк находит все пересекающиеся фрагменты с пояснением
    неоднозначности; офлайн-загрузка monaco (без CDN), slim-сборка (editor core
    + python/js/ts/md токенайзеры);
  - стартовый экран: создание/открытие/удаление проектов, серверный выбор
    папок, параметры сегментации;
  - диалог изменений (сценарий D): списки новых/изменённых/удалённых, причины
    пропусков, применение только после подтверждения;
  - прогресс фоновых задач с отменой в левой панели и статус-баре;
  - панели Allotment (изменяемая ширина); общий selection state по id фрагмента;
  - 34 frontend-теста (stores, дерево, декорации, диалоги, инспектор с моком Monaco).
- Документация: `docs/data-model.md` (сущности, ID, кэш, инвалидация).

### Изменено

- Версии: приложение 0.2.0, схема данных 2 (project.db v1).
- Зависимости backend: + sqlalchemy 2.1.4, tree-sitter 0.26.0,
  tree-sitter-python/javascript 0.25.0, tree-sitter-typescript 0.23.2
  (Windows-колёса проверены по PyPI).
- health: sqlalchemy и tree-sitter* — обязательные зависимости.

## [0.1.0] — 2026-10-15

Этап 0 — обследование среды и каркас приложения.

### Добавлено

- Структура монорепозитория: `backend/` (Python, FastAPI), `frontend/` (React, TypeScript, Vite),
  `docs/`, `scripts/`.
- Backend:
  - фабрика приложения `create_app()` с конфигурацией через переменные окружения (`ESE_HOST`,
    `ESE_PORT`, `ESE_DATA_DIR`, `ESE_FRONTEND_PORTS`);
  - эндпоинт диагностики `GET /api/health`: версия приложения и схемы данных, версия Python,
    платформа, каталог данных, статусы проверок, версии обязательных и запланированных
    зависимостей;
  - middleware `LocalOnlyMiddleware`: запросы принимаются только с loopback-`Host`
    (`127.0.0.1` / `localhost` / `::1`), изменяющие методы (POST/PUT/PATCH/DELETE) с
    нелокальным `Origin` отклоняются (защита от DNS rebinding / CSRF);
  - CORS разрешён только для локальных адресов фронтенда;
  - сервер по умолчанию слушает только `127.0.0.1:8000`;
  - тесты pytest (health + security), ruff, mypy (strict).
- Frontend:
  - каркас интерфейса в стиле «тёмная исследовательская IDE» (дизайн-токены по UI-ТЗ);
  - панель диагностики с состояниями загрузка / онлайн / офлайн и понятными подсказками;
  - типизированный API-клиент и zustand-store состояния подключения;
  - разделы SPACE / CORPUS / RELATIONS / EXPERIMENTS показаны как запланированные
    (видимая недоступность с указанием этапа, без «кнопок-обманок»);
  - vitest + @testing-library (тесты состояний панели и API-клиента), ESLint, tsc strict.
- Скрипты запуска одной командой: `scripts/dev.bat` и `scripts/dev.ps1` (Windows),
  `scripts/dev.sh` (Linux/macOS): проверка версий Python/Node, установка зависимостей,
  запуск backend и frontend.
- Скрипт всех проверок одной командой: `scripts/checks.bat` / `checks.ps1`
  (pytest, ruff, ruff format, mypy, vitest, eslint, tsc, build) с итоговой таблицей.
- Документация: `README.md`, `docs/architecture.md`, `docs/development.md`.
- Зафиксированные версии зависимостей: `backend/requirements*.txt`,
  `frontend/package-lock.json`.

### Исправлено

- Совместимость `dev.ps1` с Windows PowerShell 5.1: файл сохраняется в UTF-8 with BOM,
  пунктуация только ASCII, дочерние окна запускаются через `powershell -NoExit -Command`
  (без оператора `&&`), добавлено ожидание ответа backend перед открытием браузера.
- `pytest` запускается из любого каталога (bootstrap `sys.path` в `tests/conftest.py`
  и `pythonpath = ["."]` в `pyproject.toml`).
