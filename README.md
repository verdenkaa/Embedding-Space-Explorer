# Embedding Space Explorer

Локальный исследовательский инструмент для изучения embedding-пространств исходного кода:
загрузите папку проекта, постройте эмбеддинги фрагментов локальной моделью, исследуйте
геометрию (проекции, математические срезы, кластеры, соседи) и в любой момент проследите
**точку → фрагмент → файл и строки** и обратно.

Всё выполняется локально: без облака, аккаунтов и телеметрии.

> **Статус: Этап 3.1 (пространство, проекции, сырые оси и пресеты).** Работают: запуск одной командой, локальный
> backend с защитой loopback-only и диагностика; корпус: безопасное сканирование,
> tree-sitter-сегментация Python/JS/TS/TSX + Markdown + fallback, стабильные ID фрагментов,
> Monaco-инспектор с обратной трассировкой строк, изменения с подтверждением и индикатор
> устаревания; эмбеддинги: sentence-transformers на CPU (скачивание весов, офлайн-работа),
> режимы raw / context-enriched с явным шаблоном, .npz-кэш с явными ключами (неизменившиеся
> фрагменты не пересчитываются, batch size не инвалидирует кэш, реиндексация чистит
> устаревшие векторы), раздел EXPERIMENTS; пространство: PCA и UMAP (seed и версии
> библиотек сохраняются, кэш координат с честной отметкой устаревания), интерактивная
> 3D-сцена (React Three Fiber) и синхронная 2D-проекция, hover/клик/Ctrl-клик/выделение
> областью, трассировка точка → фрагмент → файл и строки в обе стороны, раздел SPACE.
> Раздел RELATIONS появится на этапе 4 (см. [Дорожная карта](#дорожная-карта)) — в
> интерфейсе честно помечен как недоступный.

## Требования

| Компонент | Версия | Примечание |
|---|---|---|
| ОС | Windows 10/11 | Linux/macOS поддерживаются скриптом `dev.sh` |
| Python | 3.11–3.13 (рекомендуется 3.12) | при установке отметьте «Add python.exe to PATH» |
| Node.js | ≥ 22.12 (LTS) | https://nodejs.org/ |
| RAM | ~4 ГБ свободных | GPU не требуется; torch только CPU (~200 МБ wheel) |
| Сеть | первая установка + скачивание модели | зависимости (~1 ГБ с torch) + веса модели (~470 МБ один раз) |

## Быстрый старт (Windows)

```powershell
git clone https://github.com/verdenkaa/Embedding-Space-Explorer.git
cd Embedding-Space-Explorer
scripts\dev.bat
```

Либо, если `.bat` не сработал (политика выполнения скриптов):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev.ps1
```

Скрипт проверит окружение, при первом запуске установит зависимости (несколько минут),
затем откроет два окна — **ESE backend** и **ESE frontend** — и откроет браузер на
`http://localhost:5173`. Остановка: закрыть оба окна.

Полезные параметры: `-BackendPort 8001`, `-FrontendPort 5174`, `-SkipInstall`,
`-ForceInstall` (принудительная переустановка зависимостей), `-NoBrowser`.
Зависимости ставятся только когда это нужно: повторный запуск пропускает `pip install`
и `npm ci`, если lock-файлы не менялись (иначе `npm ci` каждый раз стирал бы
`node_modules` и переустанавливал пакеты заново).

Linux/macOS: `./scripts/dev.sh` (остановка — Ctrl+C).

### Первый сценарий (этап 1)

1. На стартовом экране нажмите **«Новый проект…»**: введите имя и добавьте одну или
   несколько папок с исходниками (серверный браузер каталогов — список только имён
   директорий, содержимое файлов не читается).
2. В разделе **SPACE** (дерево корпуса — левая панель) нажмите **«Индексировать»** —
   внизу левой панели появится
   прогресс фоновой задачи (можно отменить).
3. Выберите файл в дереве — справа откроется **Monaco** (только просмотр) с подсветкой
   диапазонов фрагментов; клик по фрагменту слева прокручивает к его строкам.
4. Выделите строки в редакторе — под заголовком появится панель **«Фрагменты в
   выделении»** со всеми пересекающимися фрагментами (обратная трассировка; при
   нескольких пересечениях показывается пояснение).
5. После правок в исходниках нажмите **«Изменения»** — откроется диалог со списками
   новых/изменённых/удалённых файлов и причинами пропусков. Ничего не пересчитывается
   без кнопки **«Применить и переиндексировать»**; неизменившиеся файлы не трогаются.

Кнопка **«Диагностика»** в верхней панели — версия приложения, Python, проверки, статус
зависимостей.

### Эмбеддинги (этап 2)

1. Откройте раздел **EXPERIMENTS**.
2. Выберите модель. Если она помечена «не скачана» — нажмите **«Скачать»**
   (~470 МБ для мультиязычной по умолчанию, ~90 МБ для компактной; нужно один раз,
   дальше офлайн). Прогресс виден в строке задачи.
3. Выберите режим подготовки текста; в раскрывающемся блоке — **точный** текст, который
   будет эмбеддиться (ничего не добавляется скрытно).
4. **«Рассчитать эмбеддинги»**: batch size по умолчанию 16 (при нехватке памяти уменьшайте —
   кэш НЕ сбрасывается). Отмена между батчами сохраняет уже посчитанные векторы.
5. В таблице «Запуски» — покрытие (embedded/total, устаревшие, пропущенные) и кнопка
   «Пересчитать» (досчитывает только недостающее).

Модель по умолчанию — `paraphrase-multilingual-MiniLM-L12-v2` (384 измерения). Она
мультиязычная, но **не специализирована на исходном коде**: качество на коде — рабочая
гипотеза, которую инструмент и помогает исследовать (сравнение режимов/моделей = отдельные
запуски, векторы никогда не смешиваются).

### Пространство и проекции (этап 3)

1. После расчёта эмбеддингов откройте раздел **SPACE**: слева дерево корпуса, в центре
   сверху 3D-пространство, под ним панель проекций, снизу синхронная 2D-карта, справа
   Monaco-инспектор.
2. Переключатель видов сверху: **3D** (по умолчанию) / **2D** / **4D** / **3D+2D**.
   Рядом с ним — выпадающий список проекций **только для активного режима** (в «3D+2D»
   их два), кнопка **✕** удаляет показанную проекцию, а **«Удалить все»** очищает весь
   инвентарь проекций (с подтверждением; векторы и пресеты не затрагиваются).
   Панель построения — внизу центра. Выберите векторный запуск и метод:
   - **PCA** — линейный воспроизводимый (параметр `whiten` уравнивает дисперсии осей);
   - **UMAP** — нелинейный, искажает расстояния между кластерами (оговорка рядом);
   - **Сырые оси** — введите 2–4 индекса измерений исходного пространства (0..D-1,
     D виден по выбранному запуску): координаты выдаются **точно, без преобразований**
     (единственный режим, ничего не искажающий внутри выбранных осей); `standardize`
     уравнивает масштабы осей. Кнопка сама выводит размерность: 2 оси → 2D, 3 оси → 3D,
     4 оси → 4D.
     **Несколько 2D-графиков рядом**: перечислите пары осей через точку с запятой —
     `0,1;0,2;0,3` (до 6 пар, только для этого метода). Каждая пара становится обычной
     проекцией со своим кэшем и строкой в инвентаре, поэтому графики можно удалять
     по одному. Пресет сохраняет одну комбинацию осей, так что в мульти-режиме
     «Сохранить пресет» заблокирована.

   Нажмите **«Построить проекцию»** (для PCA/UMAP рядом есть **«Построить 4D»** —
   четыре компоненты вместо обычных 3D+2D). Координаты кэшируются: повтор с теми же
   параметрами мгновенен и не плодит запуски.
   **Пресеты**: нашли интересную комбинацию осей — введите имя и «Сохранить пресет»;
   вернуться к ней позже — выбрать в списке «пресет» (форма заполнится, построенная
   проекция подхватится из кэша, если векторы не менялись).
3. **Наведите** курсор на точку — подсказка с именем, путём и строками; **клик** — выбор:
   инспектор справа откроет файл и подсветит диапазон фрагмента; **Ctrl-клик** — добавить
   одну точку к выделению; **удерживайте Shift и тяните** — рамка выделяет область
   (Ctrl+рамка добавляет область к текущему выделению). Явных кнопок режима нет:
   пока Shift отпущен, перетаскивание вращает камеру, — поэтому выделение не сбрасывается
   при возврате к вращению. **Esc** / клик по фону снимают выделение.
4. **2D-карта** умеет то же, что 3D: колесо — масштаб (к курсору), перетаскивание — сдвиг,
   двойной клик или **⌂** — возврат к автоподгонке, слайдер «размер» в шапке панели
   (общий с 3D). Выбор фрагмента в списке корпуса подсвечивает его точку во всех видах —
   синхронизация идёт по стабильному ID фрагмента.
5. **4D-вид** — проекция с четырьмя компонентами: первые три оси образуют обычную 3D-сцену,
   а четвёртая становится слайдером **«времени»**. Слайдер задаёт позицию и толщину окна
   вдоль четвёртой оси; точки вне окна не показываются, счётчик «в слое N из M» честный.
   Кнопка **▶** проигрывает развёртку окна туда-обратно, **«весь диапазон»** возвращает
   все точки. Это окно поверх уже посчитанной проекции, а не математический срез исходного
   D-мерного пространства — срезы появятся на этапе 4 и будут подписаны отдельно.
6. После правок исходников и переиндексации проекция помечается **«устарела»** —
   пересчитайте её; точки удалённых фрагментов с карты исчезают (счётчик честный).

Полезные адреса:

- интерфейс: `http://localhost:5173`
- диагностика: `http://127.0.0.1:8000/api/health`
- Swagger: `http://127.0.0.1:8000/api/docs`

## Тесты и проверки

Всё одной командой, из любого каталога (использует собственные окружения проекта):

```powershell
scripts\checks.bat
```

Прогоняет pytest / ruff / ruff format / mypy для backend (через `backend\.venv`)
и vitest / eslint / tsc / build для frontend (через `frontend\node_modules`),
печатает итоговую таблицу и возвращает ненулевой код при провале.
Флаги: `-BackendOnly`, `-FrontendOnly`.

> `backend\.venv` и `frontend\node_modules` создаёт `scripts\dev.bat` при первом
> запуске. `.venv` находится **внутри `backend\`**, а не в корне репозитория.

Ручной запуск отдельных проверок:

Backend — из каталога `backend\`, интерпретатором venv (в системном Python
зависимостей проекта может не быть):

```powershell
cd backend
.venv\Scripts\python -m pytest        # 145 тестов (+ opt-in: pytest -m real_model — настоящая модель)
.venv\Scripts\python -m ruff check .  # линтер
.venv\Scripts\python -m mypy .        # строгая типизация
```

Frontend — из каталога `frontend\` (в корне репозитория нет package.json):

```powershell
cd frontend
npm run test        # 187 тестов: API-клиент, stores, дерево, инспектор, диалоги, эксперименты, пространство
npm run lint        # eslint
npm run typecheck   # tsc --noEmit (strict)
npm run build       # production-сборка
```

`pytest` благодаря бутстрапу в `tests/conftest.py` работает и из корня
репозитория, но канонический способ — из `backend\` интерпретатором venv.

## Структура репозитория

```
backend/            Python/FastAPI: API, конфигурация, security-middleware, тесты
  app/
    api/            HTTP-слой: schemas.py (DTO), маршруты проектов/корпуса/эмбеддингов/проекций
    core/           security.py (loopback-only), logging.py
    source_registry/ fragmentation/ storage/ jobs/   # корпус (этап 1)
    embedding_providers/ vector_store/               # эмбеддинги (этап 2)
    projection_methods/                              # PCA/UMAP + кэш координат (этап 3)
    config.py       настройки из ESE_* переменных окружения
  tests/            pytest (+ fixture-проект с известными диапазонами строк)
frontend/           React 19 + TypeScript (strict) + Vite
  src/api/          типизированный клиент (единственный канал к backend)
  src/state/        zustand-store: ui / project / experiment / space
  src/components/   TopBar, StatusBar, корпус, инспектор, эксперименты, space/ (3D/2D/4D)
  src/space/        чистая математика выделения/отображения (без three.js)
docs/               architecture.md, data-model.md, development.md
scripts/            dev.bat / dev.ps1 / dev.sh — запуск одной командой
```

## Безопасность

- Backend слушает **только 127.0.0.1**; запросы с нелокальным `Host` отклоняются (защита
  от DNS rebinding), изменяющие запросы с нелокальным `Origin` — тоже (CSRF).
- CORS разрешён только для локального фронтенда.
- Телеметрии нет; исходники никуда не отправляются.

## Устранение неполадок

| Симптом | Решение |
|---|---|
| «Не найден Python 3.11–3.13» | Установите Python 3.12 с python.org, отметьте «Add to PATH», перезапустите скрипт |
| «Не найден Node.js» / старый Node | Установите LTS с nodejs.org |
| Порт 8000/5173 занят | Закройте прошлый запуск или стартуйте с `-BackendPort`/`-FrontendPort` |
| Окна открылись и закрылись | Запустите скрипт из PowerShell и прочитайте вывод; проверьте `npm ci` вручную в `frontend/` |
| Интерфейс открылся, но «Backend недоступен» | Дождитесь запуска в окне ESE backend; нажмите «Повторить»; проверьте `http://127.0.0.1:8000/api/health` |
| PowerShell блокирует скрипт | Используйте `scripts\dev.bat` или команду с `-ExecutionPolicy Bypass` выше |
| Антивирус ругается на venv/npm | Разрешите доступ для папки репозитория (локальная разработка) |
| Не вижу папку `.venv` | Она внутри `backend\` (`backend\.venv`), создаётся при первом запуске `dev.bat` |
| `python -m pytest` из корня: `No module named 'app'` | Используйте `scripts\checks.bat`, либо запустите из `backend\` интерпретатором `.venv\Scripts\python` (в системном Python могут отсутствовать fastapi/httpx) |
| `npm run ...`: `Could not read package.json` | Команды frontend выполняются из каталога `frontend\` (или используйте `scripts\checks.bat`) |
