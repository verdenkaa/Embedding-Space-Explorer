# Модель данных

> Этап 1: корпус, фрагменты, файлы, задачи. Документ будет расширяться на
> этапах 2+ (эмбеддинги, проекции, эксперименты).

## 1. Раскладка на диске

```
<data_dir>/                          # ~/.embedding-space-explorer (ESE_DATA_DIR)
  projects/
    <project-id>/                    # id = uuid4().hex[:12]
      project.json                   # манифест (атомарная запись: tmp + os.replace)
      project.db                     # SQLite (WAL): files, fragments, jobs, meta
      cache/
        fragments/  embeddings/  projections/  neighbors/  clustering/
      experiments/
      exports/
      logs/
```

Исходники пользователя НЕ копируются: файлы читаются из выбранных корней
(`manifest.roots`).

## 2. Манифест проекта (project.json)

Pydantic-модель `ProjectManifest`:

| Поле | Описание |
|---|---|
| `schema_version` | версия схемы данных приложения (сейчас 2) |
| `app_version` | версия приложения, создавшего манифест |
| `id`, `name` | идентификатор и имя |
| `created_at`, `updated_at` | ISO-8601 UTC |
| `roots` | абсолютные пути корней (проверены при создании: существуют, не вложены друг в друга) |
| `split_options` | все параметры, влияющие на результат (см. §3) |

## 3. SplitOptions — параметры сегментации

Хранятся в манифесте; любое изменение — осознанное (влияет на фрагменты):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `max_file_size_bytes` | 1 000 000 | файлы больше — пропускаются (`too-large`) |
| `max_fragment_lines` | 200 | узлы/секции длиннее режутся на части `#partN` |
| `fallback_chunk_lines` | 80 | размер fallback-чанка |
| `fallback_overlap_lines` | 10 | перекрытие соседних чанков |
| `include_hidden` | false | индексировать ли скрытые файлы/каталоги |
| `extra_include_patterns` | [] | если заданы — индексируются ТОЛЬКО совпавшие (glob) |
| `extra_exclude_patterns` | [] | пользовательские исключения (glob) |
| `allow_symlinks_outside_root` | false | разрешить симлинки наружу корня |

## 4. Сущности SQLite (db schema v1)

### files
Строка на каждый просканированный файл. **Идентичность: `(root, rel_path)`** —
`file_id` (uuid) стабилен между сканами; изменение содержимого обновляет строку,
а не создаёт новую.

| Колонка | Описание |
|---|---|
| `id` | uuid4().hex[:12] |
| `root`, `rel_path` | ключ; `rel_path` в POSIX-стиле (`src/app.py`) |
| `abs_path` | разрешённый путь для чтения (цель симлинка, если внутри корня) |
| `size`, `mtime` | для быстрого детектора изменений |
| `content_hash` | sha256 байтов файла (для «изменён/не изменён») |
| `language` | python / javascript / typescript / tsx / markdown / null |
| `status` | `indexed` / `skipped` / `error` (+ `skip_reason`, `detail`) |
| `indexed_at` | ISO-8601 |

Пропущенные файлы НЕ хранятся в БД: причины пропуска возвращаются живьём из
каждого скана (`GET /changes → skipped[]`).

### fragments
Первичный ключ — **детерминированный стабильный ID**:

```
fragment_id = sha1(rel_path \n kind \n symbol_path \n ordinal \n content_hash)[:16]
```

Свойства (ТЗ §6.2):
- не зависит от номеров строк: вставка строк выше НЕ меняет ID;
- различается для одинакового текста в разных файлах (rel_path в хэше);
- меняется при изменении содержимого фрагмента (это ключ инвалидации кэша
  эмбеддингов на этапе 2);
- одинаков между проектами для идентичного пути+содержимого (переносимость).

| Колонка | Описание |
|---|---|
| `kind` | function / method / class / interface / type_alias / enum / object / section / chunk |
| `name` | имя символа (null для чанков) |
| `symbol_path` | цепочка области видимости: `Calc.add`; markdown: `Заголовок > Подзаголовок`; чанки: `chunk#N` и `<symbol>#partN` |
| `parent_symbol_path` | родительская область (метод → класс) |
| `start_line`, `end_line` | 1-based, включительно; декораторы входят в диапазон метода |
| `start_offset`, `end_offset` | символьные офсеты начала первой строки / конца последней |
| `content_hash` | sha256 текста фрагмента (текст = join строк диапазона по `\n`) |
| `method` | tree-sitter-python / tree-sitter-javascript / tree-sitter-typescript / tree-sitter-tsx / markdown-headings / fallback-lines |
| `ordinal` | позиция среди фрагментов с одинаковыми (kind, symbol_path) в файле |

Текст фрагмента НЕ хранится в БД: он выводится из строк файла. `GET
/fragments/{id}` перечитывает исходник, поэтому просмотр всегда показывает
текущее состояние файла; рассинхрон с `content_hash` обнаруживается проверкой
изменений (файл попадёт в `modified`).

### jobs
Фоновые задачи: `id`, `kind` (index | …), `state` (queued/running/done/failed/
cancelled), `progress_done/total`, `message`, `error`, `warnings_json`
(≤500 шт.), `params_json`, таймстемпы. Ошибки в логах и в `error` не содержат
содержимого исходников — только класс и короткое сообщение.

### meta
`schema_version` = 1. При открытии БД: версия выше поддерживаемой → понятная
ошибка (проект не открывается, но остальные работают); ниже → резервная копия
`project.db.bak-<ts>` и пересоздание (миграций v0→v1 не существует).

## 5. Поток индексирования (инкрементальный)

```
scan_roots(roots, options)              # безопасность: ../, симлинки, секреты, бинарники
  → candidates[] + skipped[] + root_errors[]
classify_changes(scan, files из БД)     # fast-path: size+mtime; иначе sha256
  → new[] / modified[] / deleted[] / unchanged_count
apply:
  deleted  → удалить строки files + fragments (CASCADE)
  new+mod  → hash → decode utf-8(replace) → fragment_file() → заменить fragments файла
  ошибки чтения → files.status=error (строка остаётся, ретрай при следующем индексе)
```

- `GET /projects/{id}/changes` — тот же поток БЕЗ записи (превью для
  подтверждения, сценарий D).
- Повторный `POST /index` идемпотентен: неизменившиеся файлы не трогаются.
- Отмена задачи проверяется между файлами; уже записанные батчи остаются
  валидными (коммит каждые 10 файлов).

## 6. Правила инвалидации (кэш)

| Событие | Что инвалидируется |
|---|---|
| изменён файл | его fragments (пересчёт); на этапе 2 — эмбеддинги изменённых фрагментов (ключ = hash(текст)+режим+модель) |
| удалён файл | его files/fragments строки |
| файл стал исключаться | как удаление (строка уходит из индекса; причина видна в skipped) |
| изменён SplitOptions | пересоздание проекта или полный реиндекс (фрагменты других параметров не переживают) |
| UI/камера/раскладка | НИЧЕГО не инвалидируется |

## 6.5 Эмбеддинги (этап 2)

### Кэш векторов: .npz на запуск

Векторы хранятся ВНЕ SQLite — по одному файлу на «запуск» (run):

```
<project>/cache/embeddings/<fingerprint>.npz
    ids          (N,)  unicode   — id фрагментов
    text_hashes  (N,)  unicode   — sha256 ТОЧНОГО подготовленного текста (ключ кэша)
    frag_hashes  (N,)  unicode   — content_hash фрагмента на момент расчёта (устаревание)
    vectors      (N, D) float32  — L2-нормализованные векторы (cosine = скалярное произведение)
```

Запись атомарная (tmp + os.replace); повреждённый .npz загружается как пустой
(пересчёт вместо падения, ТЗ §9.4).

### Идентичность запуска (fingerprint)

```
fingerprint = sha256(model_id, mode, template, params)[:16]
params      = {normalize: true, device: "cpu", dtype: "float32"}   # только влияющее на векторы
```

- **batch_size НЕ входит** в fingerprint: это деталь исполнения; уменьшение
  batch size при нехватке RAM не инвалидирует кэш (ТЗ §12).
- Разные режимы подготовки (raw / context_enriched) и разные модели — РАЗНЫЕ
  запуски; векторы между ними никогда не смешиваются (ТЗ §2.3).
- Инвентарь запусков: таблица `embedding_runs` (db schema v2, миграция v1→v2
  аддитивная: бэкап + create_all, данные не теряются).

### Ключ кэша и инвалидация

Элемент кэша идентифицируется парой (fragment_id, text_hash), где text_hash =
sha256(подготовленный текст). Пересчёт фрагмента происходит, только если:
- элемента нет (новый фрагмент / новый запуск), или
- text_hash отличается (изменился текст ИЛИ режим/шаблон — но режим/шаблон
  меняют сам запуск, так что фактически: изменился текст).

После каждого индексирования `prune_embedding_caches` удаляет из всех запусков
векторы удалённых фрагментов и векторы с несовпавшим frag_hash (изменённый
фрагмент) — устаревшие векторы не доживают до следующего расчёта (ТЗ §9.3).

### Режимы подготовки текста (ТЗ §6.3)

- `raw_fragment`: ровно текст фрагмента (строки start..end, join по \n).
- `context_enriched`: CONTEXT_TEMPLATE (path/symbol/kind/parent/language + текст).
  Шаблон хранится в строке запуска; UI показывает ТОЧНЫЙ превью через
  `GET /api/embeddings/preparation-preview` (единый источник правды).

### Провайдер и модель

- Каталог: `embedding_providers/registry.py` (ModelInfo: id, dim, ~размер,
  честное описание ограничений). По умолчанию
  `paraphrase-multilingual-MiniLM-L12-v2` (384d) — НЕ code-специфичная модель.
- Кэш весов: `<data_dir>/models` (общий для проектов); после первого скачивания
  работа офлайн. Статус «скачана» — дешёвая проверка каталога hub-кэша.
- torch только CPU (`+cpu` wheel); batch по умолчанию 16 (консервативно для
  8 ГБ RAM); отмена между батчами СОХРАНЯет посчитанные векторы (чекпоинт .npz).

## 7. ID — сводка

| Сущность | Схема ID | Стабильность |
|---|---|---|
| project | uuid4().hex[:12] | навсегда |
| file | uuid4().hex[:12], ключ (root, rel_path) | стабилен между сканами |
| fragment | sha1(path, kind, symbol_path, ordinal, content_hash)[:16] | стабилен при неизменном содержимом, независим от строк |
| job | uuid4().hex[:16] | — |
| embedding run | sha256(model, mode, template, params)[:16] | детерминирован: одинаковая конфигурация = один кэш |
